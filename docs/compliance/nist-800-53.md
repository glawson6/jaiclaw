# NIST SP 800-53 Rev. 5 (Security & Privacy Controls)

## What it is

NIST Special Publication 800-53 Revision 5 is the master catalog of security and privacy controls for federal information systems and organizations. It defines ~1000 controls grouped into 20 families. FedRAMP, FISMA, and CMMC all reference NIST 800-53 (directly or via subset standards).

Control baselines:
- **Low** — ~130 controls
- **Moderate** — ~265 controls
- **High** — ~370 controls

## What JaiClaw contributes

JaiClaw's technical controls directly satisfy approximately **40** of the NIST 800-53 Moderate baseline's 265 controls, with another **~60** partially satisfied (framework provides the primitive; adopter configures). The remaining ~165 are entirely adopter- or organization-scoped (physical, personnel, program-level).

### Highlights (federal-grade controls)

**AU-9 (Protection of Audit Information) + AU-10 (Non-repudiation)**
`HashChainedAuditLogger` in `extensions/jaiclaw-compliance/src/main/java/io/jaiclaw/compliance/audit/HashChainedAuditLogger.java`. Maintains per-tenant SHA-256 hash chain. `verifyChain(tenantId)` replays and emits `audit.integrity_violation` on the first break. This is **federal-grade tamper evidence** — an assessor can prove the audit log has not been modified since the point of last successful verification.

**SC-13 (Cryptographic Protection)**
All framework crypto uses FIPS-approved algorithms (AES-GCM-256, SHA-256, HMAC-SHA256, EC P-256, X25519, ECDH). See [fips-140-3.md](fips-140-3.md) for the full algorithm list and module-certification path.

**AC-4 (Information Flow Enforcement)**
`TenantGuard` in `core/jaiclaw-core/src/main/java/io/jaiclaw/core/tenant/TenantGuard.java` fails closed in MULTI mode. Every persistence layer (file audit logger, Redis session backend, JSON stores) enforces per-tenant path prefixing; reads defense-in-depth verify the decoded tenant field.

**AU-3 (Content of Audit Records) + augmented fields**
`AuditEvent` record in `extensions/jaiclaw-audit/src/main/java/io/jaiclaw/audit/AuditEvent.java` includes the standard fields (id, timestamp, tenant, actor, action, resource, outcome, details) PLUS the compliance-augmented fields (`lawfulBasis`, `dataCategories`, `recipients`, `retentionDays`, `consentToken`) needed for GDPR Art. 30 records of processing and HIPAA §164.312(b) audit controls.

## How to enable / disable

**Default:** framework beans exist; enforcement is off. NIST 800-53 controls that require *runtime* enforcement (HTTPS guard, audit chain, FIPS posture, LLM-call audit) are all opt-in via the compliance profile.

**Enable — the closest single-flag mapping to the NIST 800-53 Moderate baseline:**
```yaml
jaiclaw:
  compliance:
    profile: fedramp-moderate  # FedRAMP Moderate maps to NIST 800-53 Moderate
```

**Or — HIPAA + GDPR baseline (if processing PHI + EU personal data):**
```yaml
jaiclaw:
  compliance:
    profile: both
```

**Individual controls:**
- `AC-7` (unsuccessful logon) — `jaiclaw.security.rate-limit.enabled: true`
- `AU-9` (audit protection — tamper evidence) — enabled automatically by any profile that turns on `retention-enforcement`; adopter registers `HashChainedAuditLogger` as the `AuditLogger` bean
- `SC-8` (transmission encryption) — `jaiclaw.compliance.require-https: true`
- `SC-13` (cryptography) — always on for JaiClaw code (algorithms are FIPS-approved); provider certification via `jaiclaw.compliance.fips-enforced: true`

**Fully off:**
```yaml
jaiclaw:
  compliance:
    profile: none    # (default)
```

## What's adopter responsibility

- **SSP (System Security Plan)** — the document describing your specific deployment
- **POA&M (Plan of Action & Milestones)** — tracking any residual risk your assessor identifies
- **Continuous monitoring** — running the audit log through your SIEM, alerting on anomalies, quarterly control reviews
- **A&A process** — the formal Assessment and Authorization workflow with your agency
- **Physical + personnel controls** — everything in the PE, PS, MA families
- **Program-level controls** — everything in the PL, PS, AT, CP families (adopter's overall infosec program)

## What's out of scope

- 3PAO (Third-Party Assessment Organization) certification — this is a per-deployment activity
- Continuous monitoring reports to any specific PMO
- Agency-specific control tailoring (e.g., DoD-specific overlays, IC-specific extensions)
